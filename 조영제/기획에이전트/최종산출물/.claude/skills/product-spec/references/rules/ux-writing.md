# UX 라이팅 규칙 (UX Writing Rules)

기획서에 포함되는 모든 사용자 대면 텍스트의 작성 규칙입니다.
인터랙션 명세의 에러 메시지, CTA 텍스트, 안내 문구 등에 적용됩니다.

---

## 톤앤매너 (Tone & Manner)

| 원칙 | 규칙 | 예시 |
|------|------|------|
| 존댓말 기본 | 해요체 사용, 합쇼체 금지 | "저장되었습니다" (O) / "저장되었습니다" (O) / "저장됨" (X) |
| 간결하게 | 한 문장 15자 이내 권장, 최대 25자 | "결제가 완료되었어요" (O) / "고객님의 결제가 성공적으로 완료되었습니다" (X) |
| 주어 생략 | 시스템이 주어일 때 생략 | "저장했어요" (O) / "시스템이 저장했습니다" (X) |
| 사용자 탓 금지 | 에러의 원인을 사용자에게 돌리지 않음 | "카드 정보를 확인해주세요" (O) / "카드 번호를 잘못 입력했습니다" (X) |

## CTA 버튼 텍스트 (Call To Action)

| 유형 | 패턴 | 좋은 예 | 나쁜 예 |
|------|------|--------|--------|
| 주요 액션 | "동사 + 하기" | "결제하기", "저장하기" | "확인", "OK", "Submit" |
| 보조 액션 | "동사" 또는 "명사" | "취소", "닫기", "건너뛰기" | "아니오", "No" |
| 파괴적 액션 | "동사 + 하기" (빨간색) | "삭제하기", "탈퇴하기" | "삭제", "확인" |
| 확인 다이얼로그 | 구체적 동사 사용 | "삭제하기 / 취소" | "예 / 아니오" |

## 에러 메시지 패턴 (Error Messages)

### 구조: 무엇이 문제인지 + 어떻게 해결하는지

```
[문제 설명]. [해결 방법]
```

| 유형 | 패턴 | 예시 |
|------|------|------|
| 입력 오류 | "[필드]를 확인해주세요" | "이메일 형식을 확인해주세요" |
| 네트워크 오류 | "연결이 불안정해요. [해결]" | "연결이 불안정해요. 다시 시도해주세요" |
| 서버 오류 | "잠시 문제가 생겼어요. [해결]" | "잠시 문제가 생겼어요. 잠시 후 다시 시도해주세요" |
| 권한 오류 | "[필요한 조건]이 필요해요" | "로그인이 필요해요" |
| 유효성 오류 | "N자 이상 / N자 이하" | "8자 이상 입력해주세요" |

### 금지 표현

- 기술 용어 노출: "400 Bad Request", "null", "undefined", "timeout"
- 코드 노출: "ERR_001", "error code: 500"
- 영문 에러: "Something went wrong"
- 모호한 표현: "오류가 발생했습니다" (무슨 오류?)

## 안내 문구 (Guide Text)

| 위치 | 규칙 | 예시 |
|------|------|------|
| placeholder | 입력 형식 힌트 | "example@email.com" |
| helper text | 입력 조건 안내 | "8자 이상, 영문+숫자 조합" |
| tooltip | 기능 설명 | "최근 30일 데이터만 표시돼요" |
| empty state | 상황 설명 + CTA | "아직 주문 내역이 없어요. 쇼핑하러 가기" |

## 숫자/날짜/금액 표기

| 유형 | 규칙 | 예시 |
|------|------|------|
| 금액 | 천 단위 쉼표 + "원" | "29,000원" |
| 날짜 | YYYY.MM.DD | "2026.04.25" |
| 시간 | 오전/오후 HH:MM | "오후 3:30" |
| 퍼센트 | 숫자 + "%" | "45%" |
| 개수 | 숫자 + 단위 | "3개", "5건" |

---

## 이 규칙의 적용

기획서 작성 시 인터랙션 명세(8번 섹션)의 모든 사용자 대면 텍스트는 이 규칙을 따릅니다.
프로젝트별로 톤앤매너나 표기법이 다르면 이 파일을 수정하세요.
