# 폼 정책 (Form Policy)

기획서에 폼/입력 요소가 포함될 때 적용되는 정책입니다.
인터랙션 명세의 "폼 & 입력 명세(8-3)" 작성 시 참조됩니다.

---

## 유효성 검증 시점 (Validation Timing)

| 시점 | 적용 대상 | 동작 |
|------|----------|------|
| **onBlur** (포커스 아웃) | 개별 필드 검증 | 필드에서 포커스가 빠질 때 즉시 검증 |
| **onChange** (입력 중) | 이미 에러 표시된 필드만 | 에러 상태에서 사용자가 수정하면 실시간으로 에러 해제 |
| **onSubmit** (제출 시) | 전체 폼 검증 | 모든 필드 한 번에 검증, 첫 번째 에러 필드로 스크롤 |

**기본 규칙**: onBlur + onSubmit 조합. onChange는 에러 복구 시에만.

## 에러 표시 위치

| 위치 | 규칙 |
|------|------|
| **필드 하단** | 개별 필드 에러는 해당 필드 바로 아래에 표시 |
| **필드 테두리** | 에러 상태인 필드는 테두리 색상 변경 |
| **폼 상단** | 서버 에러(API 실패 등)는 폼 최상단에 배너로 표시 |
| **인라인** | 실시간 검증 결과(비밀번호 강도 등)는 필드 옆에 표시 |

**금지**: alert() 팝업으로 에러 표시

## 필수 필드 표시

| 방식 | 규칙 |
|------|------|
| 필수 표시 | 필드 레이블 뒤에 `*` 표시 |
| 선택 표시 | "(선택)" 텍스트 추가 — 필수가 대다수일 때만 |
| 기본 전략 | 필수가 더 많으면 선택만 표시, 선택이 더 많으면 필수만 표시 |

## 입력 포맷 자동화

| 필드 유형 | 자동 포맷 | 예시 |
|----------|----------|------|
| 전화번호 | 하이픈 자동 삽입 | 010-1234-5678 |
| 카드 번호 | 4자리 공백 | 1234 5678 9012 3456 |
| 사업자 번호 | 하이픈 자동 삽입 | 123-45-67890 |
| 금액 | 천 단위 쉼표 | 1,000,000 |
| 날짜 | 구분자 자동 삽입 | 2026.04.25 |

## 기본 유효성 규칙

| 필드 유형 | 규칙 | 에러 메시지 패턴 |
|----------|------|----------------|
| 이메일 | RFC 5322 형식 | "이메일 형식을 확인해주세요" |
| 비밀번호 | 최소 8자, 영문+숫자 | "8자 이상, 영문과 숫자를 조합해주세요" |
| 전화번호 | 한국 번호 형식 | "전화번호 형식을 확인해주세요" |
| URL | http/https 프로토콜 포함 | "올바른 URL을 입력해주세요" |
| 숫자 | min/max 범위 | "N 이상 N 이하로 입력해주세요" |
| 텍스트 | minLength/maxLength | "N자 이상 입력해주세요" / "N자 이하로 입력해주세요" |

## 폼 제출 동작

| 상황 | 동작 |
|------|------|
| 제출 버튼 클릭 | 버튼 비활성화 + 로딩 표시 (중복 제출 방지) |
| 검증 실패 | 첫 번째 에러 필드로 자동 스크롤 + 포커스 |
| API 호출 중 | 버튼에 스피너 표시, 텍스트 "처리 중..." 변경 |
| API 성공 | 성공 피드백 (토스트 또는 페이지 이동) |
| API 실패 | 폼 상단에 에러 배너, 입력값 유지 (초기화 금지) |
| 네트워크 오류 | "연결이 불안정해요. 다시 시도해주세요" + 재시도 버튼 |

## 미저장 데이터 보호

| 상황 | 동작 |
|------|------|
| 뒤로 가기 | 입력값이 있으면 "변경사항이 저장되지 않아요. 나가시겠어요?" 확인 |
| 페이지 새로고침 | beforeunload 이벤트로 경고 |
| 임시 저장 | 길이가 긴 폼(5개 필드 이상)은 임시 저장 기능 고려 |

---

## 이 정책의 적용

기획서에 폼이 포함되면 "폼 & 입력 명세(8-3)" 작성 시 이 정책을 기본으로 적용합니다.
프로젝트별 정책이 다르면 이 파일을 수정하세요.
