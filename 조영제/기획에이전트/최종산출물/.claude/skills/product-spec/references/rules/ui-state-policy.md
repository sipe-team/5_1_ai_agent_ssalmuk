# 로딩/에러/빈값 정책 (UI State Policy)

기획서의 "UI 상태 명세(8-2)" 작성 시 적용되는 정책입니다.
모든 화면/컴포넌트는 아래 4가지 상태를 필수로 정의해야 합니다.

---

## 4가지 필수 상태

모든 데이터 의존 화면/컴포넌트는 반드시 이 4가지 상태를 정의합니다:

| 상태 | 조건 | 필수 정의 항목 |
|------|------|--------------|
| **로딩 (Loading)** | 데이터 요청 중 | 어떤 로딩 UI? 최소 표시 시간? |
| **성공 (Success)** | 데이터 1건 이상 | 정상 표시. 이건 당연히 정의됨. |
| **빈 값 (Empty)** | 데이터 0건 | 빈 화면 메시지? CTA 버튼? |
| **에러 (Error)** | 요청 실패 | 에러 메시지? 재시도? 폴백? |

## 로딩 정책 (Loading)

### 로딩 UI 선택 기준

| 조건 | 로딩 UI | 이유 |
|------|--------|------|
| 레이아웃이 예측 가능 | **스켈레톤 UI** | 콘텐츠 영역을 미리 보여줘서 CLS 방지 |
| 레이아웃이 불확실 | **스피너** | 범용적 |
| 진행 상태가 있음 | **프로그레스 바** | 파일 업로드, 결제 처리 등 |
| 전체 화면 전환 | **전체 화면 로딩** | 결제 처리, 로그인 처리 등 |

### 로딩 시간 규칙

| 시간 | 동작 |
|------|------|
| 0~300ms | 로딩 UI 표시하지 않음 (깜빡임 방지) |
| 300ms~3s | 로딩 UI 표시 |
| 3s~10s | 로딩 UI + "시간이 좀 걸리고 있어요" 안내 |
| 10s 이상 | 타임아웃 처리 → 에러 상태로 전환 |

### 스켈레톤 UI 규칙

- 실제 콘텐츠와 같은 레이아웃으로 구성
- 애니메이션: 좌→우 shimmer (pulse 아님)
- 텍스트 영역: 회색 막대 (실제 줄 수와 유사하게)
- 이미지 영역: 회색 사각형 (실제 비율과 동일)

## 빈 값 정책 (Empty State)

### 필수 구성 요소

| 요소 | 필수 | 설명 |
|------|------|------|
| 일러스트/아이콘 | 권장 | 시각적 안내 (없어도 됨) |
| 메시지 | **필수** | 왜 비어있는지 설명 |
| CTA 버튼 | **필수** | 다음 행동 안내 |

### 빈 값 유형별 처리

| 유형 | 메시지 패턴 | CTA |
|------|-----------|-----|
| 첫 사용 | "아직 [항목]이 없어요" | "[항목] 추가하기" |
| 검색 결과 없음 | "[검색어]에 대한 결과가 없어요" | "다른 키워드로 검색" 또는 "필터 초기화" |
| 필터 결과 없음 | "조건에 맞는 [항목]이 없어요" | "필터 초기화" |
| 삭제 후 빈 목록 | "모든 [항목]을 삭제했어요" | "[항목] 추가하기" |

## 에러 정책 (Error)

### 에러 유형별 처리

| 에러 유형 | HTTP 코드 | 사용자 메시지 | 동작 |
|----------|----------|------------|------|
| 네트워크 오류 | - | "연결이 불안정해요" | 자동 재시도 1회 → 수동 재시도 버튼 |
| 서버 오류 | 500 | "잠시 문제가 생겼어요" | 수동 재시도 버튼 |
| 인증 만료 | 401 | "다시 로그인해주세요" | 로그인 화면으로 이동 |
| 권한 없음 | 403 | "접근 권한이 없어요" | 이전 화면으로 이동 |
| 없는 리소스 | 404 | "[항목]을 찾을 수 없어요" | 목록 화면으로 이동 |
| 입력 오류 | 422 | 서버 반환 메시지 표시 | 해당 필드 에러 표시 |
| 요청 제한 | 429 | "잠시 후 다시 시도해주세요" | N초 후 자동 재시도 |

### 자동 재시도 정책

| 조건 | 재시도 |
|------|--------|
| 네트워크 오류 (오프라인) | 온라인 복구 시 자동 1회 |
| 타임아웃 | 자동 1회 (간격: 2초) |
| 서버 500 | 자동 재시도 안 함. 수동만. |
| 429 (Rate Limit) | Retry-After 헤더 값 후 자동 |

### 에러 표시 위치

| 범위 | 표시 위치 |
|------|----------|
| 개별 필드 에러 | 필드 하단 인라인 |
| 개별 컴포넌트 에러 | 컴포넌트 내 에러 영역 |
| 페이지 전체 에러 | 페이지 상단 배너 또는 전체 에러 화면 |
| 백그라운드 작업 에러 | 토스트 알림 |

## 프론트엔드 엣지 케이스 정책 (Frontend Edge Cases)

기획서의 사용자 시나리오와 엣지 케이스 작성 시 아래 시나리오를 반드시 고려합니다.

### 필수 검토 시나리오

| 시나리오 | 처리 정책 |
|---------|----------|
| **오프라인 상태에서 액션** | 토스트로 "인터넷 연결을 확인해주세요" 안내. 폼 입력값은 유지. 온라인 복구 시 자동 재시도하지 않음 (사용자 재시도). |
| **동일 리소스 멀티 탭 수정** | Last-write-wins 기본. 충돌 감지가 필요한 경우(예: 문서 편집) 기획서에 명시. |
| **API 요청 중 화면 이탈** | 진행 중인 요청은 AbortController로 취소. 단, 결제/주문 등 부수효과가 큰 요청은 취소하지 않고 백그라운드 완료. |
| **토큰 만료 중 폼 제출** | 자동 토큰 갱신 → 원래 요청 재시도. 갱신 실패 시 로그인 화면으로 이동 (입력값은 복원 가능하게 저장). |
| **Optimistic Update 실패** | 즉시 UI 롤백 + 에러 토스트. 사용자가 재시도할 수 있도록 원래 액션 복원. |
| **중복 API 요청 (Race Condition)** | 최신 요청만 반영 (이전 응답 무시). 또는 요청 ID로 deduplication. |

### Optimistic Update 적용 기준

| 조건 | Optimistic | 이유 |
|------|-----------|------|
| 실패해도 부수효과 없음 (좋아요, 찜) | O | UX 반응성 우선 |
| 실패 시 금전적 영향 (결제, 주문) | X | 정확성 우선 |
| 실패 시 데이터 불일치 (재고 차감) | X | 일관성 우선 |
