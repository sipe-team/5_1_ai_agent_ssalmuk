# Anti-Slop: AI 디자인 안티패턴 통합 가이드

> 이 문서는 AI가 생성하는 디자인에서 반복되는 클리셰("슬롭")를 정의하고, 각각에 대한 구체적 대안을 제시한다.
> Step 4(제작)에서 **사전 체크**로 적용하고, Step 5(검증)에서 **사후 스캔**으로 재확인한다.

---

## 1. 절대 금지 목록 (CRITICAL — 즉시 수정)

이 항목은 **어떤 경우에도** 사용하지 않는다. 브랜드 가이드라인에 명시되어 있지 않는 한 예외 없음.

### 1.1 폰트

| 금지 | 이유 | 대안 |
|------|------|------|
| Inter 단독 사용 | AI 기본 폰트, 즉시 "AI가 만든" 느낌 | Pretendard, Noto Sans KR 등 의도적 선택 |
| Roboto 단독 사용 | Android 기본, 개성 없음 | Spoqa Han Sans Neo, Wanted Sans |
| Space Grotesk 남용 | AI 테크 프로젝트의 클리셰 | 실제 브랜드에 맞는 서체 |
| 제목과 본문에 같은 font-weight | 위계 부재 | 제목: 600-700, 본문: 400 |

### 1.2 색상

| 금지 | 이유 | 대안 |
|------|------|------|
| 보라-파랑 그라데이션 배경 | AI 학습 데이터의 최빈 패턴 | OKLCH 기반 단색 또는 브랜드 색상 |
| 그라데이션 텍스트 | 가독성 저하, AI 클리셰 | 단색 텍스트 + 배경 대비 |
| 무채색 + 보라만 쓰는 배색 | AI 기본 팔레트 | 브랜드 색상 또는 OKLCH 조화 팔레트 |
| 순수 흰색(#FFFFFF) 배경 | 차갑고 비인간적 | `oklch(0.98 0.005 hue)` 약간 따뜻한 뉴트럴 |
| 순수 검정(#000000) 텍스트 | 대비 과잉, 눈 피로 | `oklch(0.20 0.02 hue)` 약간 채도 있는 검정 |

### 1.3 레이아웃

| 금지 | 이유 | 대안 |
|------|------|------|
| 동일 크기 3-column 카드 그리드 | 가장 흔한 AI 패턴 | 비대칭 레이아웃, 다양한 크기의 카드 |
| 중첩 카드 (card-in-card) | 깊이 혼란, 시각 잡음 | 평면적 구분 또는 단일 레벨 카드 |
| 왼쪽 컬러 보더 장식 | AI가 "강조"에 남용 | 여백, 타이포 위계, 또는 배경색 |
| 히어로 + 3카드 + CTA 반복 템플릿 | 100% AI 산출물의 구조 | 콘텐츠에 맞는 고유 구조 설계 |
| 모든 모서리에 `border-radius: 1rem+` | 과도한 둥글기 | 용도에 맞는 radius (4px 소형, 8px 중형, 12px 대형 컨테이너) |

### 1.4 콘텐츠

| 금지 | 이유 | 대안 |
|------|------|------|
| 장식용 이모지 아이콘 | 유치하고 비전문적 | Lucide, Heroicons 등 아이콘 라이브러리 또는 여백 |
| 가짜 통계 ("매출 300% 증가") | 신뢰도 파괴 | 실제 데이터 또는 정직한 플레이스홀더 |
| 가짜 사용자 후기 | 비윤리적, 즉시 티남 | 실제 후기 또는 섹션 생략 |
| SVG 일러스트로 사진 대체 | 제네릭한 느낌 | 실제 사진, Unsplash, 또는 회색 플레이스홀더 |
| "혁신적인", "획기적인" 등 과장 수식어 | AI 학습 데이터 클리셰 | 구체적 가치 서술 |

## 2. 경고 항목 (WARNING — 검토 후 수정)

의도적으로 사용하는 경우 허용하되, **반드시 의도를 명시**해야 한다.

### 2.1 스타일

| 항목 | 위험 | 허용 조건 |
|------|------|----------|
| 글래스모피즘 (blur + 반투명) | AI가 "현대적"으로 남용 | 브랜드 가이드라인에 명시, 또는 사용자 명시 요청 |
| 뉴모피즘 (소프트 엠보스) | 접근성 문제 (대비 부족) | 터치 UI에서 보조적으로만, WCAG 대비 충족 시 |
| 다크 모드에서 순수 검정 배경 | 눈 피로, OLED 스미어 | `oklch(0.15 0.01 hue)` 약간 밝은 다크 |
| 그림자 3단계 이상 | 엘리베이션 복잡도 과잉 | 2단계까지 (rest, hover/active) |

### 2.2 패턴

| 항목 | 위험 | 허용 조건 |
|------|------|----------|
| 히어로 메트릭 (숫자 3개 나열) | AI가 빈 히어로 채우기에 남용 | 실제 데이터가 있고, 맥락이 뒷받침할 때 |
| 무한 스크롤 | 접근성 문제, 콘텐츠 발견 저하 | 페이지네이션 대안 검토 후 사용 |
| 햄버거 메뉴 (데스크톱) | 핵심 네비게이션 숨김 | 모바일에서만. 데스크톱은 펼친 메뉴 |
| 카드 호버 시 전체 변형 | 과도한 인터랙션, 성능 부담 | 미세한 그림자 변화 또는 보더 변화만 |

## 3. 수치 규칙 (지켜야 할 기준값)

### 3.1 타이포그래피

| 항목 | 기준 | 근거 |
|------|------|------|
| 본문 line-height | 1.7-1.8 (한국어) | CJK 문자는 라틴보다 시각적으로 무거움 |
| 본문 줄당 글자 수 | 35-40자 (한국어) | 라틴 65-75자에 해당하는 가독성 최적 |
| 제목 line-height | 1.2-1.3 | 제목은 본문보다 촘촘하게 |
| 제목:본문 크기 비율 | 최소 1.5배, 권장 2-3배 | 시각 위계 확보 |
| 최소 본문 크기 | 16px (웹), 14px (앱) | 가독성 하한 |
| letter-spacing (한국어) | -0.01em ~ 0 | 한국어는 기본 자간이 넓으므로 약간 좁히기 |
| word-break | `keep-all` | 한국어 단어 단위 줄바꿈 필수 |

### 3.2 간격

| 항목 | 기준 | 근거 |
|------|------|------|
| 기본 그리드 | 4px 단위 | 일관된 간격 시스템 |
| 섹션 간 여백 | 64-120px | 시각적 호흡 공간 |
| 컴포넌트 내부 패딩 | 16-24px | 콘텐츠 여유 |
| 터치 타겟 최소 크기 | 44×44px | Apple HIG, WCAG 2.5.5 |

### 3.3 색상

| 항목 | 기준 | 근거 |
|------|------|------|
| 텍스트:배경 대비 | 4.5:1 이상 (AA) | WCAG 2.1 |
| 큰 텍스트 대비 | 3:1 이상 | WCAG 2.1 (18px+ 또는 14px+ bold) |
| 최대 팔레트 색상 수 | Primary 1 + Accent 1-2 + Semantic 4 + Neutral 5 | 12색 이내로 통제 |
| 색상 포맷 | OKLCH | 지각적 균일성 |

## 4. Anti-Slop 체크리스트

Step 5에서 생성된 코드(.tsx/.html)에 대해 실행하는 체크리스트.

### 디자인 체크 (공통)
```
□ 폰트: Inter/Roboto가 단독 사용되지 않았는가?
□ 폰트: 제목과 본문의 weight 차이가 있는가?
□ 폰트: word-break: keep-all (또는 break-keep 클래스) 적용되었는가?
□ 색상: 보라-파랑 그라데이션 배경이 없는가?
□ 색상: 그라데이션 텍스트가 없는가?
□ 색상: 순수 흰색/검정 대신 뉴트럴 톤을 사용하는가?
□ 색상: 테마 변수 기반 팔레트를 사용하는가?
□ 레이아웃: 동일 3-column 카드 그리드가 아닌가?
□ 레이아웃: 카드 중첩(card-in-card)이 없는가?
□ 레이아웃: 왼쪽 컬러 보더 장식이 없는가?
□ 레이아웃: 모든 모서리에 과도한 border-radius가 없는가?
□ 콘텐츠: 장식용 이모지가 없는가?
□ 콘텐츠: 가짜 통계/인용이 없는가?
□ 콘텐츠: 실제 맥락을 반영한 카피인가?
□ 접근성: 텍스트:배경 대비가 4.5:1 이상인가?
□ 접근성: 터치 타겟이 44×44px 이상인가?
□ 접근성: lang="ko"가 설정되었는가?
□ 전체: "히어로+3카드+CTA" 기본 구조가 아닌가?
□ 전체: 콘텐츠에 맞는 고유 구조인가?
```

### HTML/CSS 체크 (HTML 출력 시 추가)
```
□ 코드: 하드코딩 색상(#xxx, rgb()) 없이 CSS Custom Properties(var(--color-*)) 사용하는가?
□ 코드: 인라인 style 속성 미사용인가? (이메일 타입 제외)
□ 코드: BEM 네이밍 컨벤션을 따르는가?
□ 코드: 매직 넘버(13px, 7px) 없이 토큰(var(--space-*)) 사용하는가?
□ 코드: 시맨틱 HTML 요소(header, main, section, nav, footer)를 사용하는가?
□ 코드: 모든 인터랙티브 요소에 focus-visible 스타일이 있는가?
□ 코드: 외부 프레임워크(Tailwind, Bootstrap, shadcn) 의존성이 없는가?
```

## 5. 심각도 분류 기준

| 심각도 | 정의 | 행동 |
|--------|------|------|
| **CRITICAL** | 절대 금지 목록(§1) 위반 | 즉시 수정. 사용자 보고 불필요 |
| **WARNING** | 경고 항목(§2) 해당 또는 수치 규칙(§3) 위반 | 수정 후 사용자에게 변경 사항 보고 |
| **INFO** | 개선 기회 (더 나은 대안 존재) | 보고만. 수정은 사용자 요청 시 |
