# 씬 타입 규격

> Step 1에서 씬 타입 판별, Step 4에서 제작 시 참조한다.

---

## 1. 랜딩 페이지 (`landing`) — 기본값

**목적**: 방문자를 행동(가입, 구매, 문의)으로 유도
**뷰포트**: 데스크톱 1440px 기준, 320px까지 반응형
**첫 화면**: 100vh (히어로)

### 필수 섹션
1. **히어로**: 핵심 가치 + 주 CTA (5초 내 전달)
2. **문제/해결**: 사용자 문제 정의 → 해결책 제시
3. **기능/특징**: 3-5개 핵심 기능 (동일 그리드 금지, 비대칭 권장)
4. **사회적 증거**: 고객사 로고, 사용자 수, 또는 후기 (실제 데이터만)
5. **CTA 반복**: 페이지 하단에 행동 유도 반복
6. **풋터**: 링크, 연락처, 법적 고지

### 구조 규칙
- 스크롤 내러티브: 문제 → 해결 → 증거 → 행동
- F-패턴 또는 Z-패턴 시선 흐름
- 단일 주 CTA. 보조 CTA는 시각적으로 약하게
- 섹션 간 여백: 80-120px

### 추천 폰트 페어링
- SaaS/테크: A (모던 클린)
- 콘텐츠: B (따뜻한 에디토리얼)
- 럭셔리: C (프리미엄)

### 추천 디자인 철학
- 구조주의 → 그리드 시스템, 시스템 디자인
- 기능주의 → 미니멀, 디터 람스
- 융합주의 → 에디토리얼

## 2. 대시보드 (`dashboard`)

**목적**: 데이터와 기능을 효율적으로 탐색
**뷰포트**: 데스크톱 1440px 기준, 768px 이상 (태블릿+)
**레이아웃**: 사이드바(240px) + 헤더(64px) + 메인 영역

### 필수 섹션
1. **사이드바**: 네비게이션 메뉴, 프로필, 접기 가능
2. **헤더**: 검색, 알림, 사용자 메뉴
3. **메인 그리드**: 카드 기반 데이터 표시 영역
4. **데이터 테이블**: 정렬, 필터 가능한 테이블 (필요 시)

### 구조 규칙
- CSS Grid로 레이아웃 (`grid-template-areas`, `grid-template-columns`)
- 데이터 밀도 > 장식. 여백은 최소화하되 밀집하지 않게
- 숫자 데이터: `font-variant-numeric: tabular-nums`
- 상태 색상: 시맨틱 컬러 (성공=초록, 경고=노랑, 에러=빨강)
- 카드 간격: `var(--space-4)` ~ `var(--space-6)`

### 추천 폰트 페어링
- A (모던 클린) — 대부분의 대시보드에 적합
- D (다이내믹) — 에너지/커머스

### 추천 디자인 철학
- 기능주의 → 정보 디자인
- 구조주의 → 바우하우스, 그리드 시스템

## 3. 앱 프로토타입 (`app`)

**목적**: 모바일 앱 화면을 프로토타입으로 시각화
**뷰포트**: 390×844px (iPhone 15 기준)
**레이아웃**: 상태바 + 네비게이션바 + 콘텐츠 + 탭바

### 필수 섹션
1. **상태바**: 시간, 신호, 배터리 (장식용, 고정)
2. **네비게이션바**: 뒤로, 제목, 액션 버튼
3. **콘텐츠 영역**: 스크롤 가능
4. **탭바/바텀 네비게이션**: 3-5개 메뉴 항목

### 구조 규칙
- 배경에 디바이스 프레임 포함 (선택)
- 터치 타겟: 최소 44×44px
- Safe Area 준수: 상단 59px, 하단 34px (iPhone 노치/홈 인디케이터)
- 네비게이션: iOS HIG 또는 Material Design 3 패턴 선택
- 최대 5-7 화면을 하나의 HTML에 탭/스와이프로 연결

### 추천 폰트 페어링
- A (모던 클린) — iOS/Android 네이티브 느낌
- D (다이내믹) — 커머스/소셜 앱

### 추천 디자인 철학
- 기능주의 → 미니멀
- 구조주의 → 시스템 디자인

## 4. 인포그래픽 (`infographic`)

**목적**: 데이터와 정보를 시각적으로 전달
**뷰포트**: 최대 너비 800px, 세로 스크롤
**레이아웃**: 수직 흐름, 섹션별 데이터 시각화

### 필수 섹션
1. **헤더**: 제목, 부제, 출처
2. **핵심 수치**: 가장 중요한 데이터 1-3개
3. **데이터 섹션**: 차트, 그래프, 비교 (2-4개)
4. **결론/요약**: 핵심 인사이트
5. **출처**: 데이터 출처 명시

### 구조 규칙
- 정보 위계: 제목 → 핵심 데이터 → 세부 → 결론
- 시각적 가이드라인 (시선 유도)
- 데이터 정확성 필수 (가짜 데이터 금지)
- CSS로 간단한 차트 구현 (bar chart, donut 등)
- 아이콘은 기능적으로만 사용

### 추천 폰트 페어링
- A (모던 클린) — 테크/비즈니스
- B (따뜻한 에디토리얼) — 콘텐츠/미디어

### 추천 디자인 철학
- 구조주의 → 그리드 시스템
- 기능주의 → 정보 디자인

## 5. 이메일 (`email`)

**목적**: 마케팅/트랜잭션 이메일
**뷰포트**: 600px 고정 너비
**레이아웃**: 테이블 기반 (이메일 클라이언트 호환)

### 구조 규칙
- 모든 CSS는 인라인
- 이미지: 절대 URL, alt 텍스트 필수
- 폰트: 시스템 폰트만 (웹폰트 불가)
- 최대 너비: 600px (테이블 기반)
- 링크: 밑줄 유지 (접근성)
- 다크 모드: `prefers-color-scheme` 미디어쿼리 포함

---

## 6. 카드 뉴스 (`card-news`)

**목적**: 소셜 미디어용 슬라이드형 콘텐츠
**뷰포트**: 1080×1080px (정사각) 또는 1080×1350px (4:5)
**레이아웃**: 캐러셀, 스와이프/클릭 네비게이션

### 구조 규칙
- 카드당 1개 핵심 메시지
- 텍스트 비율: 화면의 20% 이하
- 색상: 선명하지만 품위 있게
- 5-10장 카드가 적정
- 첫 장이 클릭률 결정 → 가장 공들여 제작

---

## 7. 컴포넌트 (`component`)

**목적**: 재사용 가능한 UI 컴포넌트 스니펫
**뷰포트**: 컴포넌트 크기에 맞춤
**레이아웃**: 컴포넌트 단위

### 구조 규칙
- 단일 HTML 파일에 컴포넌트 상태들을 나열하여 보여줌
- 프로젝트의 `docs/DESIGN.md` 디자인 시스템을 따름
- 상태(기본, 호버, 활성, 비활성, 에러) 모두 표시
- BEM 네이밍 + CSS Custom Properties
- 접근성: ARIA 속성 포함
