| 영역 | 기술 | 비고 |
| --- | --- | --- |
| 언어 | Python 3.13 환경 / Python 3.12+ 호환 목표 | agent 및 CLI 구현 |

| 설정 | pydantic-settings | `MARKET_AGENT_` prefix와 `.env` 지원 |
| 데이터 모델 | dataclass + Pydantic | domain model은 dataclass, agent IO는 Pydantic |
| 스케줄러 | APScheduler | 08:00, 09:00~15:30, 15:35 KST job |
| 저장소 | SQLite | watchlist, tracking snapshot 저장 |
| 시장 데이터 | MockMarketDataClient, FinanceDataReader | mock first, 국내 지수/ KRX universe read-only 확장 |
| 뉴스 데이터 | MockNewsClient, Naver Search News API | provider 응답 최소 정규화 |
| 알림 | Telegram Bot API | 기본 dry-run, 실전송은 명시 설정 필요 |
| 테스트 | pytest | provider mocking, scoring/report/agent 검증 |
| LLM | 미도입 | 향후 `llm_client` 주입 가능 구조 |
| Agent framework | 미도입 | LangGraph/CrewAI/AutoGen 없이 내부 orchestrator 사용 |

## 주요 모델

### Domain model

- `MarketSnapshot`: 시장 지수/환율 등 market context
- `NewsItem`: provider raw news 정규화 결과
- `CleanNewsItem`: category, impact hint, priority가 붙은 정제 뉴스
- `Candidate`: 후보 종목/ETF 기본 데이터
- `ScoredCandidate`: score와 score breakdown이 붙은 후보
- `PricePoint`: 장중 가상 성과 추적용 가격 데이터

### Agent model

- `MarketDataAnalysis`
- `NewsContextAnalysis`
- `MarketNewsSynthesis`
- `CandidateStaticProfile`
- `CandidateDynamicContext`
- `CandidateExplanation`
- `ReviewedPremarketNarrative`
- `CompactReportContent`

## 데이터 소스 전략

### Mock first

기본 실행은 mock data로 완전히 deterministic하게 동작한다. 테스트와 로컬 개발에서 외부 API 의존을 제거한다.

### Read-only live provider

- `FinanceDataReaderKoreaMarketDataClient`
  - `KS11`, `KQ11` 전일 지수 수집
  - `FinanceDataReader.StockListing("KRX")` 기반 후보 universe 구성
- `NaverNewsClient`
  - Naver Search News API에서 title/snippet/url/timestamp 수집
  - provider 내부에서는 분류 판단을 하지 않음

## Scoring 설계

기존 factor score는 유지하되, hybrid tagging 구조에 맞춰 breakdown을 분리한다.

| 점수 | 설명 |
| --- | --- |
| `static_score` | 유동성, asset type, index role, 기본 factor 기반 |
| `dynamic_context_score` | 오늘 시장 변수와 static sensitivity tag 매칭 기반 |
| `duplicate_penalty` | 유사 profile 후보 중복 완화 |
| `total_score` | 최종 정렬용 점수 |

## 보안 및 운영 고려 사항

- `.env`의 token/client secret은 commit하지 않는다.
- Telegram은 기본 `dry_run=True`다.
- 실전송 시 token/chat id가 없으면 실패해야 한다.
- provider 실패를 숨기지 않고 리포트에 표시한다.
- 실제 주문, broker 연동, 개인화 투자 조언은 non-goal로 유지한다.
