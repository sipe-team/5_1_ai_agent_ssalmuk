# Week 2: 워크플로우 설계

## 전체 워크플로우

한국 시장 장전 리포트 생성부터 장중 가상 성과 추적, 장마감 요약까지의 End-to-End 흐름을 정의한다.

### Phase 1: 데이터 수집 및 정규화

```
[Scheduler/CLI]
    → [MarketDataClient]
    → [NewsClient]
    → [정규화된 MarketSnapshot / NewsItem]
```

1. 08:00 `Asia/Seoul` 기준 premarket pipeline을 실행한다.
2. 시장 데이터는 기본 mock client를 사용하고, 설정에 따라 `FinanceDataReader` provider를 사용할 수 있다.
3. 뉴스는 기본 mock client를 사용하고, 설정에 따라 Naver Search News API를 사용할 수 있다.
4. 모든 데이터는 source name, data timestamp, mock/live 여부를 포함한다.
5. provider 실패 시 조용히 mock으로 섞지 않고 `데이터 수집 실패` 또는 `fallback/mock` 상태를 리포트에 표시한다.

### Phase 2: 뉴스 정제 및 시장 변수 추출

```
[Raw NewsItem]
    → [News Cleaning]
    → [NewsContextAgent]
    → category / priority / key_market_variables
```

1. 뉴스 title/snippet에서 HTML tag와 중복 표현을 정리한다.
2. deterministic rule로 뉴스 category를 부여한다.
3. category를 기반으로 시장 변수를 추출한다.
4. 예: `fx` → `fx_risk`, `rates_fomc` → `rate_policy_risk`, `geopolitical` → `geopolitical_risk`.

### Phase 3: 시장/뉴스 synthesis

```
[MarketDataAgent] + [NewsContextAgent]
    → [MarketNewsSynthesisAgent]
    → core_view / market_news_connection / intraday_watch_points
```

1. 전일 KOSPI/KOSDAQ 흐름을 보고 risk tone을 판단한다.
2. 뉴스에서 추출된 시장 변수와 시장 tone을 결합한다.
3. 공격적인 방향 판단 대신 장중 확인할 변수와 관찰 포인트를 만든다.
4. 내부 label은 report 단계에서 사용자용 한국어 표현으로 변환한다.

### Phase 4: 후보 scoring 및 hybrid tagging

```
[KRX/mock candidate universe]
    → [Scoring]
    → [CandidateTaggingAgent]
    → [CandidateContextAgent]
    → top 5 watchlist explanations
```

1. 후보 universe는 mock 또는 KRX listing 기반으로 구성한다.
2. `static_score`는 유동성, asset type, index role, 기존 후보 factor를 반영한다.
3. `dynamic_context_score`는 오늘 시장 변수와 static sensitivity tag의 연결성을 반영한다.
4. `CandidateStaticProfile`은 종목의 변하지 않는 기본 성격만 제공한다.
5. `CandidateDynamicContext`는 오늘의 market variables를 보고 dynamic tag를 생성한다.
6. 관련성이 약하면 억지로 tag를 붙이지 않고 `직접 연결성 제한적`으로 표시한다.
7. 유사 profile 후보가 여러 개면 중복 penalty 또는 역할 차별화 문구를 적용한다.

### Phase 5: 리포트 생성 및 전송

```
[Reviewed Narrative]
    → [ReportEditorAgent]
    → [CompactReportContent]
    → [TelegramClient]
```

1. compact report는 Telegram에서 바로 읽기 쉬운 한국어 문장으로 작성한다.
2. 핵심 판단, 시장 근거, 뉴스 근거, 오늘의 관찰 후보, 확인 포인트, 리스크를 포함한다.
3. `추천`, `확정`, `보장` 같은 표현은 제거한다.
4. Telegram 메시지가 길면 문단 단위로 split한다.
5. Telegram은 기본 dry-run이며, token/chat id와 dry-run 해제가 명시된 경우에만 실제 전송한다.

### Phase 6: 장중/장마감 추적

```
[Saved Watchlist]
    → [Hourly Tracking Pipeline]
    → [Closing Summary Pipeline]
```

1. premarket watchlist를 SQLite에 저장한다.
2. 09:00~15:30 KST 정규장 동안 시가 가상 매수 시나리오 성과를 추적한다.
3. 15:35 KST 기준 closing summary를 만든다.
4. 실제 주문이나 broker 계좌 변경은 수행하지 않는다.

## 실행 흐름 요약

```
uv run market-agent premarket
    → market/news load
    → clean news
    → score/rank candidates
    → agent orchestration
    → compact/full report
    → Telegram notify
    → watchlist 저장

uv run market-agent hourly
    → latest watchlist load
    → intraday prices load
    → hourly update notify

uv run market-agent closing
    → tracked prices summarize
    → closing summary notify
```

## 실패 처리 원칙

| 상황 | 처리 방식 |
| --- | --- |
| market provider 실패 | collection_failed snapshot으로 표시 |
| Naver API credential 누락 | 실패 news item으로 표시 |
| KRX universe 실패 | mock 후보 fallback, `fallback/mock` 표시 |
| Telegram dry-run | 메시지를 console에 chunk 단위 출력 |
| Telegram 실전송 credential 누락 | 명시적으로 실패 |
