# Week 1: 문제 정의

## 대상 업무

**한국 주식시장 장전 리서치 및 관찰 후보 선정 업무**

## 현재 문제

개인 투자자나 리서치 담당자가 매일 장 시작 전에 국내외 시장 흐름, 뉴스, 환율/금리 같은 macro 변수, 관련 종목 후보를 확인하려면 여러 데이터 소스를 직접 오가야 한다. 이 과정은 반복적이고 시간이 많이 들며, 리포트 품질도 작성자의 컨디션과 시간 여유에 따라 달라진다.

### 반복 빈도

**매 장 시작할때마다 **

## AI로 해결 가능한 포인트

### 1. 장전 시장 context 자동 수집

한국 전일 시장 흐름, 미국 시장 흐름, 환율/금리/뉴스 변수를 모아 동일한 report contract으로 정규화한다.

### 2. 뉴스 정제 및 시장 변수 추출

Naver Search News API 또는 mock news에서 headline/snippet을 받아 중복을 줄이고, `fx_risk`, `rate_policy_risk`, `geopolitical_risk`, `market_flow` 같은 시장 변수를 deterministic rule로 추출한다.

### 3. 관찰 후보 scoring 자동화

후보 종목/ETF를 theme relevance, catalyst, valuation, quality, risk, 유동성, asset type, index role 기준으로 점수화한다. 점수는 투자 신호가 아니라 참고용 watchlist 우선순위로만 사용한다.

### 4. Static profile과 dynamic context 분리

종목의 변하지 않는 기본 성격은 `CandidateStaticProfile`로 관리하고, 오늘의 시장 변수와 연결되는 tag는 `CandidateDynamicContext`에서 생성한다. 이를 통해 고정 설명 반복을 줄이고 재현성을 유지한다.

### 5. 사용자 친화적 compact report 생성

내부 raw label을 사용자-facing 한국어로 변환하고, Telegram에서 읽기 쉬운 compact report를 생성한다.

### 6. 안전장치와 데이터 투명성

실제 주문 기능은 만들지 않고, 모든 출력은 참고용 관찰 정보로 제한한다. 리포트에는 source name, data timestamp, mock/live/fallback 상태를 명확히 표시한다.

## 기대 효과

| 항목             | AS-IS                      | TO-BE                                   |
| ---------------- | -------------------------- | --------------------------------------- |
| 장전 리서치 준비 | 여러 사이트/뉴스 직접 확인 | agent pipeline으로 자동 수집/정리       |
| 후보 선정        | 수동 판단, 재현성 낮음     | deterministic scoring + context tag     |
| 후보 설명        | static 문구 반복           | 오늘 시장 변수 중심 설명                |
| 데이터 신뢰성    | source/timestamp 누락 가능 | report contract으로 metadata 표시       |
| 공유 방식        | 수동 정리 후 전송          | Telegram 자동 전송                      |
| 투자 안전성      | 추천처럼 오해 가능         | 관찰 후보/시나리오/리스크 표현으로 제한 |

## MVP 범위

- Python 기반 CLI agent로 구현한다.
- 기본 데이터는 mock client로 동작한다.
- 선택적으로 `FinanceDataReader`와 Naver Search News API를 read-only provider로 연결한다.
- Telegram은 기본 dry-run으로 두고, 명시적으로 해제할 때만 실제 전송한다.
- 실제 주문, broker 계좌 연동, 개인화 금융 조언은 구현하지 않는다.
