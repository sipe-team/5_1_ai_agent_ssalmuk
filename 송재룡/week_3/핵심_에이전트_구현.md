## 목표

Week 2에서 설계한 장전 리서치 agent pipeline 중 핵심 흐름을 구현하고, 기본 동작을 테스트로 검증한다.

이번 주 구현 범위는 다음에 집중한다.

| 구현 대상 | 선정 이유 |
| --- | --- |
| Market/News/Candidate agent orchestration | 장전 리포트 전체 품질을 결정하는 핵심 흐름 |

## 1. Agent orchestration 구현

### 구현 파일

```
src/market_agent/agents/
├── market_data.py
├── news_context.py
├── synthesis.py
├── candidate_context.py
├── risk_review.py
├── report_editor.py
├── orchestrator.py
└── models.py
```

### 구현 내용

- `MarketDataAgent`: 시장 snapshot을 risk tone과 사용자용 시장 근거로 변환
- `NewsContextAgent`: 정제 뉴스에서 key market variables와 중요 뉴스 근거 추출
- `MarketNewsSynthesisAgent`: 시장과 뉴스를 결합해 core view, watch points 생성
- `CandidateContextAgent`: 후보별 관찰 이유, 연결 변수, 확인 포인트, 리스크 생성
- `RiskReviewAgent`: 투자 권유로 오해될 수 있는 표현 완화
- `ReportEditorAgent`: Telegram compact report용 content 생성
- `PremarketAgentOrchestrator`: 위 agent들을 순서대로 실행

### 실행 순서

```
MarketDataAgent
→ NewsContextAgent
→ MarketNewsSynthesisAgent
→ CandidateContextAgent
→ RiskReviewAgent
→ ReportEditorAgent
```

### 검증 결과

- agent orchestration 순서를 테스트로 고정했다.
- market/news/candidate input이 compact report content로 이어지는 것을 검증했다.
- raw internal label이 사용자-facing report에 그대로 노출되지 않도록 테스트했다.

## 2. Hybrid candidate tagging 구현

### 구현 파일

```
src/market_agent/agents/candidate_profiles.py
src/market_agent/agents/candidate_tagging.py
src/market_agent/agents/candidate_context.py
```

### Static profile

`CandidateStaticProfile`은 종목의 변하지 않는 기본 성격만 담는다.

```python
CandidateStaticProfile(
    ticker="005930",
    name="삼성전자",
    asset_type="stock",
    market="KOSPI",
    sector="반도체",
    industry="메모리/대형 수출주",
    index_role="KOSPI 대형주",
    base_sensitivity_tags=["fx_sensitive", "foreign_flow", "large_cap_defense", "semiconductor_cycle"],
    source="static_profile",
    confidence=0.9,
)
```

정책:

- 주요 대형주/ETF만 static dictionary로 관리한다.
- unknown ticker는 `분류 미확인`으로 처리한다.
- static profile은 오늘의 관찰 이유를 직접 만들지 않는다.

### Dynamic context

`CandidateDynamicContext`는 오늘의 market variables와 static sensitivity tag를 연결한다.

```python
CandidateDynamicContext(
    ticker="005930",
    dynamic_tags=["환율 민감도 확인"],
    matched_market_variables=["fx_risk"],
    evidence=["환율 부담 + fx_sensitive"],
    reason="반도체/메모리 profile이 환율 부담과 연결됩니다.",
    confidence=0.78,
    data_gaps=[],
)
```

적용 rule:

| Market variable | Static sensitivity | Dynamic tag |
| --- | --- | --- |
| `fx_risk` | `fx_sensitive` | 환율 민감도 확인 |
| `risk_off` | `large_cap_defense` | 대형주 방어력 확인 |
| `rate_policy_risk` | `rate_sensitive` | 성장주 밸류에이션 부담 확인 |
| `geopolitical_risk` | `oil_cost` | 원가/유가 리스크 확인 |
| `market_flow` | `market_beta` | 지수 방향성 확인 |

관련성이 약하면 `직접 연결성 제한적` tag와 낮은 confidence를 반환한다.

### Candidate explanation

`CandidateExplanation`은 static profile 설명이 아니라 오늘의 관찰 이유 중심으로 작성한다.

포함 항목:

- `static_profile_summary`
- `today_observation_reason`
- `connected_variables`
- `score_reasons`
- `watch_points`
- `risks`

## 3. Candidate scoring 개선

### 구현 파일

```
src/market_agent/scoring.py
src/market_agent/models.py
```

### 변경 내용

`ScoredCandidate`에 `score_breakdown`을 추가했다.

```python
{
    "static_score": 78.5,
    "dynamic_context_score": 2.5,
    "duplicate_penalty": 0.0,
    "total_score": 81.0,
}
```

점수 정책:

- `static_score`: 기존 factor score + 유동성 + asset type + index role
- `dynamic_context_score`: 오늘 시장 변수와 static sensitivity tag 연결성
- `duplicate_penalty`: 삼성전자/삼성전자우처럼 유사 profile 후보 중복 완화
- `total_score`: 최종 ranking 기준

compact report에는 숫자 breakdown을 직접 노출하지 않고, 사람이 이해할 수 있는 점수 근거로 표시한다.

## 4. Compact report 및 Telegram 전송 구현

### 구현 파일

```
src/market_agent/reports.py
src/market_agent/clients/telegram.py
```

### Compact report 예시

```text
📌 프리마켓 리포트
생성: 2026-05-01 10:48 KST
데이터 상태: 시장=live / 뉴스=live / 관찰 후보=live
후보 universe: live KRX 기반. 설명은 현재 시장/뉴스 context 기준입니다.

🧭 핵심 판단
- KOSPI -1.38%, KOSDAQ -2.29%로 두 지수가 모두 약세였고...

🔎 왜 이렇게 보나
- 시장 근거: KOSPI -1.38%, KOSDAQ -2.29%
- 뉴스 근거:
  - FOMC 금리 동결 / Naver Search News API / 2026-04-30 19:20

👀 오늘의 관찰 후보
- 삼성전자 (005930)
  - 이유: KOSPI 대형주 성격을 가진 반도체 후보로, 오늘은 환율 민감도 확인 관점에서 관찰합니다.
  - 연결 변수: 환율 부담
  - 점수 근거: 유동성·자산유형·지수 역할 기반 기본 점수 반영, 오늘 시장 변수와 후보 민감도 매칭 반영
  - 확인: 환율 방향, 외국인 수급
  - 리스크: 금리·환율·외국인 수급 변화가 리스크 요인입니다.
```

### Telegram 처리

- 긴 report는 `TELEGRAM_SAFE_MAX_LENGTH=3500` 기준으로 split한다.
- dry-run이면 chunk를 console에 출력한다.
- dry-run 해제 시 token/chat id가 없으면 실패한다.
- 실제 전송은 Telegram Bot API `sendMessage`를 사용한다.
