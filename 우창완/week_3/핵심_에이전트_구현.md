# Week 3: codegrep 시맨틱 검색 및 Agent 모드 구현

## 목표
codegrep의 핵심 기능인 **시맨틱 검색 엔진**을 먼저 구현한 뒤, 이를 도구로 활용하는 **Agent 모드**를 구현하고 기본 동작을 검증한다.

## 구현 대상 선정 이유

| 구성 요소 | 선정 이유 |
|---|---|
| 시맨틱 검색 엔진 | codegrep의 근간이 되는 핵심 기능으로, Agent 모드 및 모든 상위 기능의 전제 조건 |
| Agent 오케스트레이터 (ReAct Loop) | 자연어 질의를 스스로 분해·반복 검색하는 제어 중추로, 시맨틱 검색의 활용도를 극대화 |
| 도구 어댑터 (Tool Adapter) | 시맨틱 검색과 파일 읽기·git 조회를 Agent의 표준 도구로 노출하는 필수 인터페이스 |

## 1. 시맨틱 검색 엔진 구현

### 기능 정의
- 코드·문서 파일을 청킹·임베딩하여 벡터 DB에 색인
- 자연어 쿼리를 받아 의미 기반 유사도 검색 결과 반환

### 입출력 스펙

**인덱싱 입력:**
​```json
{
  "path": "./src",
  "max_file_size": 1048576,
  "max_file_count": 1000
}
​```

**검색 입력:**
​```json
{
  "query": "결제 재시도 로직",
  "path": "./",
  "max_results": 10
}
​```

**검색 출력:**
​```json
{
  "results": [
    {
      "file": "src/payment/PaymentRetryHandler.java",
      "lines": "42-98",
      "snippet": "public class PaymentRetryHandler { ... }",
      "score": 0.91
    }
  ],
  "total_indexed": 342,
  "query_time_ms": 120
}
​```

### 구현 방식
- 임베딩 모델: OpenAI `text-embedding-3-small`
- 벡터 DB: ChromaDB / Qdrant ??
- 청킹 전략: tree-sitter 기반 함수·클래스 단위 청킹, 일반 텍스트는 의미 단위 분할
- 인덱싱: 파일 해시 기반 증분 업데이트

## 2. Agent 오케스트레이터 구현

### 기능 정의
- 자연어 질의를 입력받아 ReAct 루프 기반으로 검색 계획을 세우고 실행
- 최대 반복 횟수 및 토큰 예산 내에서 도구를 호출하며, 출처가 포함된 답변 생성

### 입출력 스펙

**입력:**
​```json
{
  "query": "결제 실패 시 재시도 로직이 어디에 구현되어 있고 왜 이렇게 설계됐어?",
  "path": "./",
  "max_iterations": 3,
  "token_budget": 20000
}
​```

**출력:**
​```json
{
  "answer": "결제 재시도 로직은 PaymentRetryHandler에 구현되어 있으며, 지수 백오프 방식을 사용합니다.",
  "citations": [
    {
      "file": "src/payment/PaymentRetryHandler.java",
      "lines": "42-98",
      "reason": "재시도 핵심 로직"
    }
  ],
  "iterations": 3,
  "tokens_used": 12450,
  "confidence": 0.88
}
​```

### 구현 방식
- LLM: Claude Sonnet 4.6 (tool use / structured output)
- 루프 전략: ReAct (Reason → Act → Observe) 패턴
- 종료 조건: 답변 생성 완료 / 최대 반복 도달 / 토큰 예산 초과

## 3. 도구 어댑터 구현

### 기능 정의
- Agent가 호출 가능한 도구 세트를 표준 인터페이스로 제공
- 시맨틱 검색 엔진 및 툴 스펙으로 래핑

### 입출력 스펙

**입력 (도구 호출 예시):**
​```json
{
  "tool": "semantic_search",
  "arguments": {
    "query": "payment retry logic",
    "max_results": 10
  }
}
​```

**출력:**
​```json
{
  "results": [
    {
      "file": "src/payment/PaymentRetryHandler.java",
      "lines": "42-98",
      "snippet": "public class PaymentRetryHandler { ... }",
      "score": 0.91
    }
  ]
}
​```

### 구현 방식
- 도구 목록: `semantic_search`, `exact_search`, `read_file`, `list_directory`
- 인터페이스: JSON Schema 기반 tool definition
- 에러 처리: 각 도구 실패 시 Agent가 인지 가능한 구조화된 에러 반환

​```

## 4. 기본 동작 검증 계획

### 검증 시나리오

| # | 시나리오 | 검증 항목 |
|---|---|---|
| 1 | 샘플 리포 인덱싱 | 파일 수집·청킹·임베딩이 오류 없이 완료되는지 |
| 2 | 단순 키워드성 자연어 검색 | 관련 파일이 Top-K에 포함되는지 |
| 3 | 의도 기반 자연어 검색 | 키워드가 직접 일치하지 않아도 관련 코드 반환 여부 |
| 4 | Agent 단순 위치 탐색 질의 | 1~2회 반복 내 정확한 파일/라인 반환 |
| 5 | Agent 복합 질의 (코드 + 설계 의도) | 서브쿼리 분해 및 교차 탐색 수행 여부 |
| 6 | 존재하지 않는 기능 질의 | 허위 답변 없이 "찾을 수 없음" 반환 |
