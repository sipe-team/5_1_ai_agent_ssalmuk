# Week 5: 그동안의 진행 결과 정리

## 1. 문제 정의 (Week 1)

**대상 업무**: 서비스 장애 대응 및 컴플레인 처리 프로세스

### 핵심 Pain Point
- 장애/컴플레인 발생 시 담당자 파악 → 분류 → 이력 조회 → 1차 조치까지 평균 **60분 이상** 소요 (주 3~5회 반복)
- AI Agent로 개발 속도는 빨라졌지만 **콘텐츠 배포 속도는 그대로** → 마지막 단계에서 개발자 의존으로 병목 발생

### AI 적용 포인트
1. **어드민 개발** — 노코드 툴보다 AI 코딩이 더 빠른 시대, 콘텐츠 배포 입력 UX 개선
2. **콘텐츠 유사도 탐지 (RAG)** — 연애 질문 의미적 유사도 VoC 대응, 세그먼트별 맞춤 질문 확장 대비
3. **번역 시스템 내재화** — 사내 glossary·톤앤매너 일관성 유지
4. **업무 프로세스 일원화** — 흩어진 반복 업무 파악 후 자동화

---

## 2. 어드민 개발 (Week 2~3)

### AI Agent 병렬 활용 전략
- `develop` → 1차 통합 브랜치 → 작업별 worktree로 분기 → 페이지별 Agent 세션 병렬 실행
- 각 작업 완료 시 코드 확인 → 1차 브랜치 머지 → 검증
- 전체 완료 후 1차 브랜치 → `develop` squash PR

### Agent 가이드 (Agent.md / 스킬)
- 로케일 등 공통 변수 사용 가이드
- 버튼 설계 (검증 단계 포함 구조) 및 로직 주입 형태
- 테이블 설계, 필터·선택 패턴
- 입력 시 파일명 패턴 기반 자동 선택

### 안정화 과정에서의 학습 (Week 3)
- **AI 결과물 QA 방법론**이 새 과제로 부상
- worktree 분리는 좋지만 **완료된 worktree 관리 부담** 발생
- 대응: `claude -w` 활용 + 1차 머지 흐름으로 단순화
- IntelliJ에서 worktree 디렉토리는 `exclude` 처리하여 인덱싱 부하 제거

## 3. 옵시디언 플러그인 — 주식 캘린더 (Week 3)

- 투자 일정·인사이트 기록을 위해 노션 → 옵시디언 마이그레이션
- 산업/관련 기업 등 속성 값 정리
- AI와 함께 Plan 단계에서 막연했던 구조를 명확히 하는 과정 자체가 핵심
- 기존 데이터 마이그레이션 작업 병행
- **팁**: 주식 캘린더 데이터는 토스 캘린더가 정확도 높음

## 4. 강의/발표 자료 제작 자동화 (Week 3)

1. md 파일로 발표 요소 작성
2. **md → HTML 변환 스킬** 제작
   - 슬라이드 사이즈·기본 레이아웃
   - 레이아웃별 템플릿
   - 디자인 스킬·테마 반영
3. **GitHub Action + GitHub Pages** 통합으로 빠른 배포·피드백
- HTML 산출물은 환경 제약 없이 사용 가능

## 5. 어드민 MCP — 지식 베이스 연동 (Week 4)

### 배경
- 사내 AI Agent를 슬랙봇 형태로 전사 활용 중
- 어드민 재개발 + 프로세스 일원화와 맞물려 **앱 콘텐츠 정보 전달 채널** 필요

### 계획
- 기존 Notion 문서 MCP로 1차 수집·가공
- 전사 프로세스/가이드 문서 수집
- MCP 서버로 오픈할 **도메인 기능 정리**
- **권한 재설계**

### 기대 효과
- 권한이 결합된 MCP로 사내 데이터 안전 처리
- 코드/문서 검색 토큰 비용 절감

## 6. 종합 — 지금까지의 패턴

| 영역 | AS-IS | 진행 결과 |
|------|-------|-----------|
| 어드민 개발 | 개발자 최종 검수 병목 | worktree+Agent 병렬화로 빠른 개발, QA 방법론 정립 중 |
| 콘텐츠 유사도 | 개별 문의·비체계적 | RAG 적용 계획 수립 |
| 번역 시스템 | 콘텐츠 업무 주요 병목 | 일관성 자동화 방향 설계 |
| 업무 프로세스 | 흩어진 반복 업무 | 어드민 + MCP 기반 일원화 진행 |
| 개인 생산성 | 노션·수동 자료 제작 | 옵시디언 플러그인, md→HTML 자동화 |

### 반복적으로 검증된 작동 패턴
- **Plan 단계 AI 협업** → 막연한 구조의 명료화
- **worktree 병렬 + 1차 머지 브랜치** → 검증 가능한 병렬 개발
- **Agent.md/스킬로 가이드 외재화** → 일관된 산출물
- **GitHub Action 자동 배포** → 짧은 피드백 루프
